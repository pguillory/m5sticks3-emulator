### Design Decisions Made
- **Headless architecture**: QEMU runs headless (`-display none`), controlled via QMP over unix socket. Socket at `.qemu.sock` in working directory (one emulator per worktree).
- **No naked QMP**: Thin wrapper script (`emu.sh`) hides QMP handshake and JSON. Worth the ~150 lines.
- **WiFi approach**: ELF symbol patching stays. No attempt to support raw .bin WiFi. Accepted.
- **Unit test framework**: QEMU's qtest framework. Tests boot ESP32-S3 machine and poke registers.

### RESOLVED: BQL Starvation (was CRITICAL BLOCKER)
**Status: FIXED.** The firmware boots fine on current main. The BQL starvation was caused by tight CPU loops during ROM init, not a missing peripheral.

**Fix (committed ec118967fb):**
- Dual-timer approach: VIRTUAL clock timer (50ms, fires during CPU execution) + REALTIME clock timer (500ms, fires on wall clock)
- Added `-icount shift=4,align=off,sleep=on` to emu.sh — throttles CPU relative to virtual time
- Result: reliable 10-second boots, QMP responsive throughout

**QMP confirmed working:** Screenshots, register queries, GPIO injection all work after firmware reaches WAITI.

### Button Fix (Corrected Root Cause)
**Initial theory was WRONG.** Buttons are NOT read from M5PM1 PMIC. M5Unified reads ESP32 GPIO 11/12 directly:
```
btn_rawstate_bits = ((!gpio_in(GPIO_NUM_11)) & 1) | ((!gpio_in(GPIO_NUM_12)) & 1) << 1;
```
The M5PM1 I2C traffic during init is configuring GPIO3 as audio PA control, not buttons.

**Actual root cause:** `x-gpio-set-pin` was setting `gpio_in` but firmware had `gpio_enable` set for pins 11/12 (output mode). When output is enabled, `GPIO_IN` returns `gpio_out` not `gpio_in`, making injection invisible.

**Fix:** QMP handler now clears `gpio_enable` before setting input level. Also added M5PM1 register 0x12 (charging status, returns 0xFF = discharging) for correctness.

**SDL UI note:** The SDL UI (`ui/sdl2-m5sticks3.c`) uses GPIO 11/12 — this is CORRECT, not wrong as previously thought.

**Status:** VERIFIED WORKING. Committed c029f7e5fb.
